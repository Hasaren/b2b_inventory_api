# B2B 재고·매출·거래처 관리 API

기업의 상품, 거래처, 주문, 재고 및 운영 지표를 관리하기 위한 FastAPI 프로젝트입니다.

## 현재 구현 기능

- 상품 등록, 검색, 페이지네이션
- 거래처 등록 및 조회
- 재고 입출고 조정, 안전재고 이하 필터링
- 주문 생성과 재고 자동 차감
- 재고 부족 주문 차단
- 상품·거래처·주문·매출·부족재고 대시보드 집계
- 더미 주문 데이터 생성기 (`dummy_orders.py`)
- 주문 내역 CSV 일괄 적재 (`POST /imports/orders`)
- 상품별 주간 수요예측 API (`GET /forecasts`, `GET /forecasts/products/{product_id}`)
- FastAPI TestClient 기반 정상·실패 테스트
- FastAPI + PostgreSQL Docker Compose 실행

```text
app/
├── core/config.py
```

`Router → Service → Repository → Database`로 책임을 분리했습니다.

수요예측의 계산 로직(`forecasting.py`)은 DB와 FastAPI를 모르는 순수 계산 코드로 분리했습니다. 주문 데이터 표만 넣으면 예측값이 나오므로 DB 없이 노트북과 테스트에서 그대로 사용할 수 있습니다.

## 더미 데이터 생성

수요예측 테스트용으로 제조·산업 부품 12개 상품, 거래처 15곳의 주문 CSV를 생성합니다.

```bash
python dummy_orders.py --days 365 --seed 42 --out data/dummy_orders.csv
```

예측 모델이 패턴을 찾는지 검증할 수 있도록 다음 패턴을 심어두었습니다.

- 상품별 증감 추세
- 무작위 상품 3개의 약 3주짜리 프로젝트성 수요 급증
- 평일 중심 주문 (주말은 거의 없음)
- 월초(1~7일) 정기 발주로 주문 1.25배
- 2% 확률의 대량 주문 (수량 4배)

날짜는 실행한 날을 기준으로 "오늘로부터 과거 N일"을 만듭니다. 같은 seed여도 실행한 날짜에 따라 요일 배치가 달라져 결과가 조금 다를 수 있습니다.

## 주문 내역 CSV 일괄 적재

`POST /imports/orders`에 CSV 파일을 올리면 거래처, 상품, 주문을 한 번에 저장합니다.

| 쿼리 | 설명 |
|---|---|
| `initial_stock` | CSV로 새로 생성되는 상품의 시작 재고 (기본 0) |

**CSV 컬럼** (UTF-8, 10MB 이하)

```text
order_id, ordered_at, business_number, company_name, sku, product_name, quantity, unit_price
```

**동작**

- `order_id`가 같은 행은 하나의 주문으로 묶고, 행마다 주문 상품으로 저장합니다.
- 처음 보는 사업자번호와 SKU는 거래처와 상품으로 자동 생성합니다. 이미 있으면 기존 것을 사용합니다.
- 주문 상태는 `confirmed`로 저장하고, 과거 거래 적재용이므로 재고는 차감하지 않습니다.
- `ordered_at`에 시간대가 없으면 UTC로 처리합니다.
- 거래처, 상품, 주문을 한 트랜잭션으로 저장하므로 하나라도 실패하면 전부 롤백됩니다.

**오류 응답**

| 상태 | 원인 |
|---|---|
| 400 | UTF-8이 아닌 파일, 빈 파일, 필수 컬럼 누락, 데이터 행 없음 |
| 413 | 파일이 10MB 초과 |
| 422 | 행 검증 실패 (몇 행의 어떤 값이 문제인지 메시지로 안내) |

> `order_id`를 저장하지 않으므로 같은 파일을 두 번 올리면 주문이 중복됩니다. 다시 올리려면 DB를 비운 뒤 올려야 합니다.

**사용 순서**

```bash
python dummy_orders.py --days 365 --seed 42 --out data/dummy_orders.csv
uvicorn app.main:app --reload
# Swagger UI(/docs)에서 POST /imports/orders 에 CSV를 업로드 (initial_stock 예: 500)
```

## 상품별 주간 수요예측

| 엔드포인트 | 설명 |
|---|---|
| `GET /forecasts` | 전체 상품 예측. 예측 대상(`forecasts`)과 제외 상품(`excluded`)으로 나눠서 응답 |
| `GET /forecasts/products/{product_id}` | 상품 하나의 예측 |

| 쿼리 | 설명 | 범위 / 기본값 |
|---|---|---|
| `weeks` | 앞으로 몇 주를 예측할지 | 1~12 / 4 |
| `history_weeks` | 함께 보여줄 최근 실적 주 수 | 0~52 / 12 |

**상품 하나 조회 시 오류**

| 상태 | 원인 |
|---|---|
| 404 | 없는 상품 |
| 422 | 예측 대상이 아닌 상품 (주문이 드문 상품, 사유를 메시지로 안내) |

**응답 예시** (값은 예시)

```json
{
  "product_id": 1,
  "sku": "P-004",
  "name": "케이블 하네스",
  "model": "random_forest_per_product",
  "backtest_wape": 0.389,
  "active_week_ratio": 1.0,
  "history": [{ "week_start": "2026-09-21", "quantity": 232.0 }],
  "forecast": [
    { "week_start": "2026-10-05", "quantity": 210.4 },
    { "week_start": "2026-10-12", "quantity": 198.7 }
  ]
}
```

`backtest_wape`는 마지막 8주를 학습에서 빼고 한 주씩 맞혀본 오차이며, 상품마다 예측을 얼마나 믿을 수 있는지 보여줍니다. 낮을수록 좋습니다.

### 예측 방식

1. **주간 집계**: 확정 주문(`confirmed`)의 (상품, 주문 시각, 수량)을 월~일 주 단위로 합산합니다. 주문이 없던 주는 0으로 채우고, 아직 끝나지 않은 이번 주와 주 중간에 시작한 첫 주는 제외합니다.
2. **예측 대상 선정**: 최근 52주 중 주문이 있었던 주의 비율이 **80% 이상**인 상품만 예측합니다. 간헐적 수요 전용 기법은 사용하지 않으므로 주문이 드문 상품은 제외하고, 제외 사유를 응답에 담습니다.
3. **입력값**: 1~4주 전 수량(`lag_1~4`), 그 4주 평균, 그 주에 매월 1~7일이 며칠 포함되는지(월초 정기 발주 효과)
4. **모델**: 상품마다 `RandomForestRegressor`를 따로 학습합니다.
5. **여러 주 예측**: 한 주씩 예측하고, 그 예측값을 다음 주의 입력으로 넣어 이어서 예측합니다. 먼 주일수록 정확도는 떨어집니다.
6. **학습 시점**: 주문 데이터가 바뀌었을 때만 대상 선정, 백테스트, 학습을 다시 합니다. 같은 데이터에서는 학습 결과와 예측 표를 재사용하므로 첫 호출만 몇 초 걸립니다.

## 모델 선정과 검증

더미 데이터(52주 x 12개 상품)로 `ipynb` 파일에서 검증했습니다. 오차 지표는 WAPE(`|오차| 합 / 실제 판매량 합`)이며, 0.3이면 전체 판매량의 30% 정도 틀렸다는 뜻입니다. 마지막 N주를 학습에서 빼고 다음 1주를 맞혀보는 방식으로 평가했습니다.

### 모델 비교 (`notebooks/model_comparison.ipynb`)

| 테스트 구간 | 4주 평균 | 랜덤포레스트(합쳐서) | 랜덤포레스트(상품별) |
|---|---|---|---|
| 마지막 8주 | 0.405 | 0.381 | **0.378** |
| 마지막 12주 | 0.398 | 0.399 | **0.378** |
| 마지막 16주 | 0.415 | 0.398 | **0.383** |

- 4주 평균은 모델 없이 최근 4주 평균을 그대로 예측값으로 쓰는 비교 기준입니다.
- 상품별 랜덤포레스트가 세 구간 모두에서 가장 낮은 오차를 보였고, 4주 평균 대비 약 5~8% 개선됐습니다.
- 합쳐서 학습한 모델은 구간에 따라 4주 평균과 비슷하거나 소폭 개선에 그쳐 일관성이 부족했습니다.
- 따라서 **상품별 랜덤포레스트**를 채택했습니다.

### 예측 대상 선정 기준 (`notebooks/active_ratio_threshold.ipynb`)

| 기준 | 남는 상품 | 평균 WAPE | 최악 WAPE |
|---|---|---|---|
| 0.5~0.6 | 12 | 0.582 | 1.264 |
| 0.7 | 11 | 0.520 | 0.994 |
| 0.75~0.85 | 10 | 0.473 | 0.717 |
| 0.95 | 7 | 0.397 | 0.691 |
| 1.0 | 6 | 0.348 | 0.389 |

- 주문이 드문 상품(P-006, P-007)은 오차가 판매량에 가깝거나 넘어서 제외했습니다.
- 기준을 0.75~0.85로 바꿔도 같은 10개 상품이 남아 결과가 기준값에 민감하지 않았습니다.
- 0.9 이상으로 올리면 평균 오차는 낮아지지만 예측 가능한 상품 수가 줄어드는 트레이드오프가 있어, 그 구간의 가운데인 **0.8**을 채택했습니다.

### 한계

- 상품 12개와 한 번의 더미 데이터로 정한 기준이라, 데이터에 따라 모델 순위와 기준선 근처 상품은 달라질 수 있습니다. 모델 간 오차 차이도 크지 않고 테스트 구간이 서로 겹칩니다.
- 2주 이상 앞의 예측은 이전 예측값을 입력으로 쓰기 때문에 정확도가 더 낮습니다. 1주 앞 예측이 가장 신뢰할 수 있습니다.
- 판매량이 적은 상품은 분모(실제 판매량 합)가 작아 WAPE가 크게 나옵니다. 제외 사유가 "주문이 불규칙해서"인지 "판매량이 적어서"인지는 완전히 구분하지 못했습니다.
- 수요를 확정 주문 수량으로 봅니다. 재고 부족으로 거절된 주문은 기록에 남지 않아 실제 수요보다 적게 잡힐 수 있습니다.
